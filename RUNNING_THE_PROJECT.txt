SPATIAL GESTURE CONTROL - RUNNING THE PROJECT
================================================

This guide covers development and local builds on Windows, macOS, and Linux.
Run all project commands from the repository root unless stated otherwise.

Repository:
https://github.com/meanOtaku/gesture-controls

Official Tauri prerequisite reference:
https://v2.tauri.app/start/prerequisites/


1. COMMON REQUIREMENTS
----------------------

All operating systems require:

- Git
- Node.js 20 or newer (Node.js 22 LTS is recommended)
- npm
- The current stable Rust toolchain installed through rustup
- A graphical desktop session when launching the Tauri window

Confirm the tools are available:

  git --version
  node --version
  npm --version
  rustc --version
  cargo --version

If Rust is not installed:

Linux/macOS:

  curl --proto '=https' --tlsv1.2 https://sh.rustup.rs -sSf | sh

Windows PowerShell:

  winget install --id Rustlang.Rustup

Restart the terminal after installing Node.js, Rust, or system build tools.


2. GET THE SOURCE AND INSTALL JAVASCRIPT DEPENDENCIES
-----------------------------------------------------

  git clone https://github.com/meanOtaku/gesture-controls.git
  cd gesture-controls
  npm install

For an existing checkout, use the reproducible lockfile installation:

  git pull
  npm ci


3. LINUX SETUP
--------------

Debian / Ubuntu:

  sudo apt update
  sudo apt install -y \
    libwebkit2gtk-4.1-dev \
    build-essential \
    curl \
    wget \
    file \
    libxdo-dev \
    libssl-dev \
    libayatana-appindicator3-dev \
    librsvg2-dev \
    patchelf \
    pkg-config

Fedora:

  sudo dnf check-update
  sudo dnf install -y \
    webkit2gtk4.1-devel \
    openssl-devel \
    curl \
    wget \
    file \
    libappindicator-gtk3-devel \
    librsvg2-devel \
    libxdo-devel
  sudo dnf group install "c-development"

Arch Linux:

  sudo pacman -Syu
  sudo pacman -S --needed \
    webkit2gtk-4.1 \
    base-devel \
    curl \
    wget \
    file \
    openssl \
    appmenu-gtk-module \
    libappindicator-gtk3 \
    librsvg \
    xdotool

Start the development application:

  npm run tauri dev

Build installable Linux packages:

  npm run tauri build

Linux notes:

- The Tauri window cannot open from a headless SSH-only terminal without a
  graphical X11 or Wayland session.
- If pkg-config reports that webkit2gtk-4.1, librsvg, or appindicator is
  missing, install the corresponding development package for your distribution.


4. macOS SETUP
--------------

Supported development systems should use macOS Catalina 10.15 or newer.
Install the Xcode Command Line Tools:

  xcode-select --install

Alternatively, install full Xcode and launch it once to finish setup.

Start the development application:

  npm run tauri dev

Build the macOS application and disk image:

  npm run tauri build

macOS notes:

- The first build can take several minutes while Rust compiles dependencies.
- macOS may warn about unsigned local builds. Code signing and notarization are
  separate release-distribution steps and are not needed for normal development.
- Apple Silicon and Intel Macs use the same project commands; build on the target
  architecture unless you intentionally configure cross-compilation.


5. WINDOWS SETUP
----------------

Install these Windows dependencies:

1. Microsoft C++ Build Tools:
   https://visualstudio.microsoft.com/visual-cpp-build-tools/

   In the installer, select "Desktop development with C++".

2. Microsoft Edge WebView2 Evergreen Runtime:
   https://developer.microsoft.com/en-us/microsoft-edge/webview2/

3. Rust through rustup, if it is not already installed:

   winget install --id Rustlang.Rustup

Open a new PowerShell terminal after installation.

Clone and install, if not already done:

  git clone https://github.com/meanOtaku/gesture-controls.git
  cd gesture-controls
  npm install

Start the development application:

  npm run tauri dev

Build the Windows executable and installers:

  npm run tauri build

Windows notes:

- If MSI creation fails while running light.exe, enable the Windows VBSCRIPT
  optional feature under Settings -> Apps -> Optional features -> More Windows
  features, then restart Windows if prompted.
- WebView2 is included with many current Windows installations, but installing
  the Evergreen Runtime explicitly avoids missing-runtime failures.


6. PROVIDE HEAD-TRACKING DATA
-----------------------------

The desktop backend listens only on:

  127.0.0.1:4243/UDP

For real tracking, run sony-head-tracker on the same computer and configure it
to emit protocol-version-2 JSON UDP packets to 127.0.0.1:4243:

  https://github.com/NicholasSlattery/sony-head-tracker

Start the tracker before or after the desktop application. The dashboard changes
to Connected after receiving its first valid packet.

To test the dashboard without headphones, leave the desktop app running and send
the included simulated packet from a second terminal.

Linux/macOS:

  python3 head-tracking/scripts/send_sample.py

Windows PowerShell:

  py head-tracking/scripts/send_sample.py

The sample sends one packet, so the dashboard will briefly connect and then
return to its waiting state. Run it repeatedly to send additional samples.

If the dashboard never connects:

- Confirm both programs are on the same machine.
- Confirm the sender targets 127.0.0.1 UDP port 4243.
- Check that no other process is already bound to UDP port 4243.
- Check the terminal running Tauri for malformed-packet or version errors.
- Confirm the JSON packet uses protocol version 2 and includes all required
  metrics.


7. RUN TESTS AND QUALITY CHECKS
-------------------------------

Frontend tests plus Tauri icon/config validation:

  npm test

TypeScript checking:

  npm run typecheck

Production frontend build:

  npm run build

Rust protocol and UDP provider tests:

  cargo test -p spatial-protocol -p head-tracking --all-targets

Rust formatting check:

  cargo fmt --all -- --check

Rust linting:

  cargo clippy -p spatial-protocol -p head-tracking \
    --all-targets --all-features -- -D warnings

Existing Python interoperability tests (requires uv):

  uv run --directory head-tracking --with pytest pytest -q


8. BUILD OUTPUT
---------------

After this command:

  npm run tauri build

Tauri prints the exact generated artifact paths. Build products are normally
placed under:

  target/release/bundle/

The platform-specific folders may contain Linux packages, a macOS app/DMG, or
Windows MSI/NSIS installers depending on the host OS.

Native desktop installers should normally be built on their target operating
system. The GitHub Actions workflow also builds the project on Ubuntu, macOS,
and Windows to catch platform-specific failures.


9. FRONTEND-ONLY PREVIEW
------------------------

To preview only the React dashboard without compiling or launching Tauri:

  npm run dev --workspace @spatial-gesture/desktop

Then open:

  http://127.0.0.1:1420

This mode is useful for UI development, but it does not start the Rust UDP
listener or expose native Tauri functionality. Use "npm run tauri dev" for the
complete application.
